A Wi-Fi flash drive for 3D printers.

Drop a print job from your desk. Walk to the printer. Press print. No cloud, no account, no printer firmware changes.

The problem

Plenty of 3D printers accept jobs only from USB media and have no networking of their own. Every print becomes the same errand: slice at your desk, copy to a stick, carry it across the workshop, plug it in, print. Then somebody else needs the stick.

PrintDrop replaces the stick. It plugs into the printer's USB port and appears as an ordinary flash drive — a USB mass storage device with a FAT32 volume, nothing unusual as far as the printer is concerned. At the same time it joins the local network and serves a web interface, so files can be dropped onto it from any browser.

How it works

  1. Upload from your desk

    Drag a .gcode file onto the web UI. Progress, transfer rate and estimated time are shown per file.

  2. The card is handed back

    PrintDrop briefly withdraws the media from the printer while it writes, then re-presents it. The printer re-reads its file list and the new job is simply there.

  3. Walk over and print

    The file appears in the printer's own menu, exactly as if it had been copied from a USB stick.

What's inside

ESP32-S3

A 4 MB, no-PSRAM DevKitC-1 driving an SD card over SPI and presenting it through TinyUSB mass storage.

Self-hosted UI

62 KB of plain HTML, CSS and JavaScript served from a LittleFS partition. No CDN, no external requests, no build step.

Local only

Wi-Fi credentials live in the device's NVS. Nothing leaves the network, and there is no service to sign up for.

Safe sharing

USB and Wi-Fi access to the same card is serialised, so a file written over the network cannot corrupt what the printer is reading.

The hard part

A USB host caches the file allocation table. Writing to the card behind its back is how these devices normally corrupt themselves. PrintDrop holds to three rules:

  • One lock. Every access to the card, from either side, is serialised.
  • Withdraw before writing. The media is taken away from the printer for the duration of a write, then handed back so it re-reads the table.
  • Remount when the host writes. If the printer changes sectors, the device throws away its own cached view before trusting it again.

Mass storage callbacks take the lock with a short timeout and fail the transfer rather than block, so a slow upload can never stall a printer mid-job.

Measured

485KB/s read
248KB/s write
62KB web UI
32GB card tested

Throughput is bounded by driving the card in SPI mode rather than 4-bit SDIO. A 20 MB print job uploads in roughly 80 seconds — the card, not the network, is the limit.
